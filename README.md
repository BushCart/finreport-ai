# FinReport AI

**FinReport AI** - система интеллектуального анализа финансовой отчетности компаний на основе Retrieval-Augmented Generation (RAG).

## 1. Описание проекта

FinReport AI - ML-система, предназначенная для автоматизации поиска, извлечения и анализа информации из финансовой отчетности компаний.

Система позволяет пользователям задавать вопросы на естественном языке, получать ответы на основе финансовых документов и проверять достоверность информации по ссылкам на первоисточники.

## 2. Бизнес-проблема

Финансовые аналитики тратят значительное время на изучение корпоративной отчетности, поиск финансовых показателей и сравнение результатов деятельности компаний за разные периоды.

Ручной анализ документов имеет несколько недостатков:

- Высокие временные затраты на поиск информации.
- Необходимость обработки больших объемов документов.
- Риск ошибок при извлечении и сопоставлении финансовых показателей.
- Сложность проверки выводов без обращения к первоисточникам.

**Цель проекта** - сократить время анализа финансовой отчетности, сохранив точность результатов и возможность их проверки.

## 3. Предлагаемое решение

FinReport AI будет предоставлять следующие возможности:

- Загрузка и обработка финансовой отчетности в формате PDF.
- Извлечение текста, таблиц и метаданных из документов.
- Семантический и полнотекстовый поиск.
- Генерация ответов с использованием LLM и найденного контекста.
- Предоставление ссылок на исходные документы.
- Извлечение и сравнение финансовых показателей за разные периоды.
- Оценка качества поиска и генерации ответов.

Пример пользовательского запроса:

«Как изменилась операционная прибыль компании за последние три года и какие факторы повлияли на ее динамику?»

## 4. Архитектура системы

Предполагаемая архитектура включает:

1. **Document Ingestion** - загрузка и обработка PDF-документов.
2. **Text Processing** - извлечение текста, сегментация и обработка метаданных.
3. **Embedding Model** - преобразование текстовых фрагментов в векторные представления.
4. **Vector Database** - хранение векторов и метаданных.
5. **Hybrid Retrieval** - комбинированный семантический и полнотекстовый поиск.
6. **Reranking** - повторное ранжирование найденных фрагментов.
7. **LLM Generation** - генерация ответов на основе найденного контекста.
8. **Response Validation** - проверка корректности ответов и ссылок на источники.
9. **REST API** - интерфейс взаимодействия с системой.
10. **Monitoring** - мониторинг качества, производительности и стоимости запросов.

## 5. Технологический стек

Предполагаемые технологии:

| Компонент | Технология |

| Язык программирования | Python 3.11+ |
| Backend API | FastAPI |

## 6. Источники данных

Планируется использовать открытые финансовые документы компаний.

Потенциальные источники:

- [SEC EDGAR](https://www.sec.gov/edgar) - корпоративная финансовая отчетность.
- Годовые отчеты публичных компаний.
- Открытые финансовые документы и отчетность эмитентов.

Доступность, форматы и условия использования данных будут проверены перед реализацией.

## 7. Метрики качества

**ML-метрики:**

- `Recall@K` - полнота поиска релевантных фрагментов.
- `nDCG@K` - качество ранжирования.
- `Faithfulness` - соответствие сгенерированных ответов источникам.
- Точность извлечения финансовых показателей.

**Системные и бизнес-метрики:**

- Время ответа системы (`p95`, `p99`).
- Стоимость одного успешно обработанного аналитического запроса.
- Сокращение времени выполнения аналитической задачи.
- Доля ответов с корректными ссылками на источники.

Целевые значения метрик будут определены после исследования данных и оценки baseline.

## 8. Границы проекта (MVP)

В первую итерацию входят:

- Обработка ограниченного набора финансовых отчетов.
- Поиск информации с использованием RAG.
- Генерация ответов на финансовые вопросы.
- Предоставление ссылок на документы.
- Сравнение качества нескольких подходов к поиску.
- Предоставление API для выполнения запросов.

В первую итерацию не входят:

- Автоматизированные инвестиционные рекомендации.
- Прогнозирование стоимости акций.
- Алгоритмическая торговля.
- Автономное принятие финансовых решений.

## 10. Разработка и проверка качества кода

Для обеспечения качества кода используются:

- **Ruff** - линтинг и форматирование Python-кода.
- **pre-commit** - автоматическая проверка перед созданием коммитов.
- **GitHub Actions** - выполнение проверок в CI.

Установка инструментов:

```bash
python -m pip install ruff pre-commit
pre-commit install
```

Запуск проверок:

```bash
ruff check .
ruff format --check .
pre-commit run --all-files
```
